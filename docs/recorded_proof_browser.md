# Browser-local recorded proof import

The public static preview now includes a **recorded proof viewer** at `/recorded`, linked from the workspace sidebar. It accepts a `proof.json` manifest generated by the private `qloo_operator_workspace` CLI. This is a browser-local file import, not a server-backed agent session.

## Operator route

1. Freeze an agent proposal, review a private recorded Qloo capture and persist an explicitly acknowledged revision-1 candidate-only repair using the existing operator tools.
2. Run `python -m ofc_engine.qloo_operator_workspace` against that saved SQLite revision, the same proposal and the original private Qloo capture. Add `--historical` for an older response. The CLI writes a private HTML page and a checksum-bound `proof.json` manifest.
3. Open `/recorded` in the local or hosted static OFC preview, choose the **generated** `proof.json` and inspect the Evidence OFF/ON, bounded change, pending recheck and journal digests. The browser checks the manifest's exact recorded schema and SHA-256 digest before rendering. Importing the file makes **no API request**; nothing is stored in browser local storage or uploaded.

The browser accepts only a known, restricted recorded-only result schema. It refuses any manifest asserting provider authentication, completed independent verification, cleared rechecks, verified full plan, external execution or release approval. Candidates remain anonymized aliases. The source manifest must still be handled as an operator artifact; do not commit it or include real provider payloads on the public site. The manifest digest shows file integrity, **not** provider authenticity or proof that a network request happened.

The new browser page does not ask for `QLOO_API_KEY`, clear pending revisions, conduct a fresh provider request or expose mutation endpoints. The hosted preview stays read-only and the original `/proof` lab stays synthetic. The transition from recorded result to a trusted, independently verified live action remains a separate milestone. Demonstration footage must clearly label the recorded evidence and may not imply that live cultural suitability was certified.

## Qualification

The normal CI checks verify the static allowlist, strict local-only trust boundary, browser JavaScript syntax, and unchanged public read-only endpoints. Chromium qualification additionally loads a synthetic **test-only manifest** into `/recorded` at desktop and narrow/mobile widths, confirms no network requests occur after import, and rejects both a checksum-tampered document and a release-authorized forgery.
